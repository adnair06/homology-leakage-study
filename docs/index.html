Homology Leakage in Protein Property Prediction

An investigation into how similarity between training and test sequences inflates the reported accuracy and other metrics of protein classifiers.
We ran one pipeline on two datasets. On enzyme classification, removing similar proteins from the test set costs 7 points of ROC-AUC. On the widely used DeepSol solubility benchmark it costs nothing at all, and the reason turns out to be a problem in how that dataset was built.

1 · The question

A protein is a chain of smaller units called amino acids. There are twenty standard kinds, and each one is written as a single letter, so a protein can be stored as a string of text such as MKVLAHHG and so on. The models in this project read that string and predict a property of the protein.

Such a model could be doing one of two quite different things, and this project is an attempt to measure which.

The first possibility is that the model has learned some chemistry. Proteins with many electrically charged amino acids and few long water-repelling stretches tend to stay dissolved in water. A model that picks up on patterns like this will work on any protein it is given, including one that is unlike anything it was trained on.

The second possibility is that the model is doing a lookup. If a test protein is 70% identical to a training protein that was soluble, then predicting "soluble" will usually be correct. The model has not learned anything about chemistry. It has learned to recognise proteins it has already seen relatives of.

Both strategies score well when the test set is chosen at random, because in a random test set most proteins do have a relative in the training data. The two only give different answers on proteins that have no close relative in training. For those, the lookup strategy has nothing to copy, so its accuracy drops.

What this project measures

We measure the size of that drop. To do it we use a nearest-neighbour baseline, which is a method that does no learning at all. For each test protein it finds the most similar training sequence and copies its label, which means it performs pure lookup based on how similar proteins are to one another.

That baseline tells us the best a pure lookup approach can do. We can then compare the trained models against it. If a model scores close to the baseline, then most of what the model does is lookup. If it scores clearly higher on proteins that have no close relative, then it has learned something beyond recognising families.

The question, stated precisely How much of the measured performance of sequence-based protein classifiers is explained by copying labels from similar training proteins, and do these classifiers keep any predictive power for proteins that have no close relatives in the training data?

One thing should be said at the start. Whatever survives after we remove similar proteins is not automatically chemistry. It is whatever generalises beyond family membership. That could be real biophysics, but it could also be protein length, or some artefact of how the data was collected. The controls described later exist to rule out the less interesting of those explanations.

2 · How we plan to answer it

Two proteins are called homologous when they descend from a common ancestor, which usually means their sequences are visibly similar. We will use the word homolog for such a relative. The whole question above is about what happens when homologs are present on both sides of a train/test split, so the first thing we need is a way to control that.

Idea one: build two splits that differ in only one way

A train/test split divides the data into a part the model learns from and a part used to measure it. We build two different splits of the same data.

If the two test sets are the same size and have the same mix of labels, then any difference in score between them can be attributed to homology rather than to one test set simply being bigger or differently balanced.

Idea two: measure what pure lookup achieves

The nearest-neighbour baseline described in section 1 is run on both splits. Because it does nothing except copy a neighbour's label, its score tells us how much of the task can be solved by similarity alone. Any trained model can then be compared against that number instead of against zero.

Idea three: report results by how similar each test protein is

A single average score hides a lot. For every test protein we also record the similarity of its closest training protein, then group the test proteins into bands by that similarity and score each band separately. This shows whether performance depends on having a relative available, and it is the view that most published results do not report.

3 · The dataset, and what we found in it

Our first task is predicting protein solubility, which is whether a protein stays dissolved in water or clumps together when it is produced in the laboratory. This matters practically, because a protein that clumps cannot easily be studied or manufactured.

We use the dataset introduced by the DeepSol paper (Khurana et al., 2018), obtained from SeprotHub/Dataset-Solubility on Hugging Face. One row is one protein, with its amino acid sequence, a label of soluble or insoluble, and a field marking which split it belongs to. There are 71,419 rows in total, divided into 62,478 for training, 6,942 for validation and 1,999 for testing.

What the labels actually mean

The labels record whether a protein was produced in soluble form in E. coli bacteria during large structural biology projects. This is not the same as the protein being soluble in general. It is the outcome of one particular experiment in one particular organism. Published work that compared these labels against independently measured solubility found that about 18.6% disagreed even for sequences that were completely identical. Thus there is an upper limit on the accuracy any model can reach here, and no modelling choice can get past it.

Two details of how the dataset was built

Before using the data we read how it was assembled, and two decisions turn out to matter for everything that follows.

First, repeated or near-repeated sequences within the training data were reduced using a tool called CD-HIT, which removes sequences that are more than a given percentage identical to another sequence already kept. The threshold used was 90%. This is a weak filter, so many close relatives remain inside the training data.

Second, every sequence that was at least 30% identical to anything in the official test set was deleted from training. The official test set is therefore already controlled for homology.

This has a practical consequence for us. The effect we want to measure has already been removed from the official test split, so we cannot measure it there. We therefore work with the 69,420 training and validation sequences as a single pool and build our own splits from it. The official test split is kept aside as an external reference point.

Basic checks on the data

We checked the data before modelling. There are no exactly duplicated sequences. The alphabet is exactly the twenty standard amino acids, with no unusual characters. Sequence lengths run from 19 to 1,697 with a median of 275.

We also checked the balance of labels, which is the proportion of soluble proteins. The training and validation parts are both 41.7% soluble, while the official test part is 50.0% soluble. Someone balanced the test set deliberately. This is worth knowing because accuracy can be compared between two sets only when their label balance is similar.

What we found: two populations of His-tags

When proteins are produced in the laboratory, a short extra piece is often attached to them so they can be purified afterwards. The most common is a run of six or more histidine amino acids, written as a run of the letter H, and known as a His-tag. It is not part of the natural protein. It is added by the laboratory, and which version is used depends on the laboratory and its protocol.

Searching for runs of six or more H characters finds 32,203 sequences, which is 45% of the dataset. When we separate those by where the run sits, two distinct groups appear, and they behave in opposite ways.

There is a possible biological explanation. A tag at the start sits where the cell begins building the protein and may interfere with folding, while a tag at the end is added once most of the protein has already formed. But it is equally possible that the laboratories which preferred end tags were working on easier proteins. Sequence data alone cannot separate those two explanations. We therefore removed both kinds of tag before any modelling, with a check that no sequence was reduced below 20 amino acids.

One thing we decided not to do

The original project proposal included adding 3,723 extra sequences from a database called TargetTrack, chosen by matching them for similarity against proteins already present. The aim was to increase the number of test proteins that have a close relative available, since that is the effect we want to measure. We dropped this, because every added sequence is labelled soluble. Adding them would shift the label balance and would insert exactly the kind of near-identical pairs whose influence we are trying to measure, so we would end up measuring our own procedure.

4 · Building the experiment

Grouping similar proteins together

To build a split that separates families, we first need to know which proteins are related. We use MMseqs2, a tool that compares protein sequences and groups similar ones together. We chose it over older tools such as BLAST because it is fast enough to compare every sequence against every other sequence at this scale.

Two sequences are placed in the same cluster, meaning the same group of relatives, only if they pass two separate tests.

  • Sequence identity is the percentage of positions that match once the two sequences have been lined up against each other. We require at least 30%.
  • Coverage is how much of each protein is involved in that lining up. We require at least 80%, and we require it of both sequences rather than just one.

Both tests are needed. Identity on its own only describes the part that lined up, and says nothing about how large that part was. Two proteins that share one short region can reach high identity over that region while being unrelated everywhere else. Requiring coverage as well removes those cases. Requiring it of both sequences stops a short protein from matching simply because it fits inside a much longer one.

We chose 30% identity because it is the same threshold the DeepSol authors used when separating their own test set, so our split is at least as strict as theirs. We chose 80% coverage because it is the MMseqs2 default and is the value most commonly used in this literature.

Building the two splits

The cluster-aware split is built first, using StratifiedGroupKFold from scikit-learn. This divides the data into five equal parts while obeying two constraints: it never splits a cluster across parts, and it keeps the proportion of soluble proteins roughly equal in each part. We take one of the five parts as the test set, giving an 80/20 division.

The random split is built afterwards, and we force its test set to have the same number of proteins as the cluster-aware one. It is also stratified, which means the proportion of soluble proteins is kept the same as in the full pool. We build the cluster-aware split first because it is the constrained one. Its size is determined by where the cluster boundaries happen to fall, so the flexible split is the one that should be made to match.

Turning sequences into numbers

A model cannot read a string of letters directly, so each sequence is converted into a list of numbers called features. We use two different ways of doing this, chosen to differ in how much sequence order they capture.

  • Amino acid composition is the fraction of the sequence made up by each of the twenty amino acids. This gives 20 numbers per protein and ignores the order they appear in.
  • 3-mer counts record how often each run of three consecutive amino acids appears. There are 8,000 possible runs, so this gives 8,000 numbers per protein and captures a small amount of local order.

We use all 8,000 possible 3-mers rather than selecting the most common ones. The list of possible 3-mers is fixed by the alphabet before any data is seen, so no information from the test set can leak in through the choice of features. Most of those 8,000 numbers are zero for any given protein, so the data is stored as a sparse matrix, which records only the non-zero entries.

Both feature sets are divided by their own total, so that each protein's numbers sum to one. This removes protein length from the features. Without it, a long protein would have larger counts of everything simply because it is long.

The models

We use logistic regression, which is a model that weights each feature and adds the weights up to produce a probability. We use it deliberately rather than something more powerful. Holding the model fixed and weak means that any difference we see between the two splits can be attributed to the split itself rather than to the model's capacity. The cost of this choice is discussed in the limitations.

Logistic regression uses regularisation, which discourages large weights to stop the model fitting noise. Its strength is controlled by a value called C, where a smaller C means stronger discouragement. We choose C by cross-validation, which splits the training data into parts, trains on some and measures on the rest, and repeats. This is done entirely inside the training set, so the test set plays no part in choosing it.

On the cluster-aware split, the inner cross-validation also respects clusters. If it did not, relatives would appear on both sides of the inner folds and we would reintroduce the exact problem the split exists to prevent, while choosing a setting for a project about that problem.

The decision threshold

Logistic regression outputs a probability between 0 and 1. To turn that into a yes or no answer we need a threshold, and the usual default is 0.5. We used that default and did not tune it. To check whether that cost us anything, we swept every possible threshold afterwards and found the one that gives the best score.

Thus there is no real benefit to be had from a different threshold here, and our main scores are unaffected by the choice.

One further point. The main scores we report are ROC-AUC and PR-AUC, which are explained in the next section. Both are calculated across all possible thresholds at once, so they do not depend on this choice at all. Only accuracy, F1 and MCC do.

5 · The first result

How we score the models

Before the numbers, a short description of each measure we report, since they answer different questions.

  • Accuracy is the fraction of predictions that are correct. It is easy to read but misleading when one label is more common than the other, because always guessing the common label already scores well.
  • Balanced accuracy averages the accuracy on each label separately, which removes that problem.
  • F1 combines how many of the predicted positives were right with how many of the true positives were found.
  • MCC, the Matthews correlation coefficient, measures agreement between predictions and truth on a scale from −1 to 1, where 0 means no relationship at all. It is the measure least affected by unequal label counts, so we rely on it most.
  • ROC-AUC is the probability that the model gives a randomly chosen positive protein a higher score than a randomly chosen negative one. A value of 0.5 means the ordering is no better than chance. It does not depend on where the decision threshold is placed.
  • PR-AUC is similar but focuses on performance on the positive label, which makes it more informative when positives are rare.

For reference, the simplest possible model always predicts the more common label. On the solubility pool that gives 58.3% accuracy and an MCC of 0. Any useful model must beat that.

Each model was trained and measured on both splits. The quantity we care about is the gap between them, because that is how much of the random-split score depended on test proteins having relatives available.

This is not the expected result. We removed homology from the test set, and measured performance was unchanged. Either homology does not inflate results on this task, or something is preventing us from seeing it.

6 · Working out why

To investigate, we looked at the assumption the whole idea rests on. Copying a neighbour's label only works if similar proteins usually share a label. We can check that directly. For every test protein we compare its label with the label of its closest training protein, and group the results by how similar that pair is.

 Agreement rises steadily across five bands, exactly as biology predicts, and then drops from 75% to 10% in a single step.

The first five rows behave normally. More similar proteins more often share a label, which is why homology transfer works at all. The last row does not. Among the most similar pairs, which are the ones where copying should work best, the labels disagree about 90% of the time.

We checked individual pairs to confirm this is not an error in our code. Test protein 15610 and training protein 27560 have sequences that are character for character identical, and one is labelled soluble while the other is labelled insoluble. Across the 1,491 proteins in this band, the lookup baseline achieves an MCC of −0.80, meaning its predictions are close to being systematically inverted.

The most likely explanation Random mistakes in labelling would produce agreement near 50%, spread evenly across all bands. What we see instead is a sharp change at one specific point. That point is 90% identity, which is exactly the threshold DeepSol used when removing near-duplicate sequences with CD-HIT. If that removal was applied to each label separately, then pairs of near-identical sequences sharing a label would have been reduced to one representative, while pairs with opposing labels would not look like duplicates and would survive. We state this as a coincidence in position rather than a proven cause, since the preprocessing code is not available to check.

This also explains why we did not try to repair the problem by adding sequences, as the original proposal suggested. Augmenting the data would have filled that band back in, but every added sequence carries the same label, so the restored agreement would come from our own choice of what to add rather than from biology.

Why the two splits ended up equal

With this in hand, the result in section 5 can be explained. Two effects of similar size work against each other.

The cluster-aware split still contains a lot of partial homology. 3,601 of its test proteins still have a closest match in the 30 to 40% band. Our clustering required 30% identity and 80% coverage together, so pairs that match strongly across part of their length were never grouped and were free to end up on opposite sides.

The random split contains three times as many of the unreliable pairs. 1,491 of its test proteins sit above 90% identity, against 445 in the cluster-aware split. This happens because clustering sends near-identical proteins to the same side by construction. Those proteins score at chance level, which pulls the random split's average down by roughly as much as the extra homology pushes it up.

Thus the result is not that nothing happened. Two measurable effects of comparable size acted in opposite directions. Removing close homology also removed most of the unreliable labels, because they were the same proteins.

7 · A second dataset as a check

At this point we have a result we cannot interpret. We do not know whether our method failed to detect homology inflation, or whether this dataset cannot show it. The way to separate those is to run the identical pipeline on a dataset where the labels are known to be reliable. If the effect appears there, the method works.

The second task

We chose to predict whether a protein is an enzyme, which is a protein that speeds up a chemical reaction. Many proteins are not enzymes, so this is a sensible yes or no question.

The labels come from UniProt, a curated protein database. A protein that has been shown to catalyse a reaction is given an EC number, which is a code identifying the reaction. If a protein has one, it is an enzyme.

We took positives from proteins whose catalytic activity has experimental support, using the query (reviewed:true) AND (cc_catalytic_activity_exp:*), giving 50,160 entries. We required experimental support because many EC numbers in the database were assigned by copying them from a similar protein, and using those would mean measuring the database's own use of homology rather than biology.

Negatives came from (reviewed:true) NOT (ec:*) AND (cc_function:*) AND (existence:1), giving 65,708 entries. These are proteins with no EC number that have a described function and have actually been observed, rather than only predicted from a gene sequence.

We then removed sequences shorter than 50 or longer than 1,500 amino acids, and sequences containing non-standard characters. Sequences under 50 produce too few 3-mers to describe and are matched unreliably by search tools. Sequences over 1,500 are usually several proteins joined together, which breaks the coverage rule. The non-standard characters had to go because two of them, U and O, appear almost only in enzymes, so keeping them would hand the model part of the answer. This leaves 101,304 proteins at 44.0% enzyme.

Two things follow from this, and both of them matter.

The 3-mer result is real. All five folds show a positive gap, ranging from 0.044 to 0.070, with a mean of 0.055. However, the fold we reported above is the largest of the five. The typical gap is therefore closer to 0.055 than to 0.070, and we should quote it that way.

The composition result is not real. Its gaps average 0.004 with a spread of 0.008, and two of the five folds are negative. The figure of 0.016 we reported is again the most favourable fold. We cannot claim that the composition model exploits homology at all.

Enzyme function is strongly preserved between related proteins, a search for the nearest relative exploits that almost perfectly, and logistic regression on 3-mer counts is a poor substitute for it.

The exception, and it is the important one For test proteins with no detectable relative, the lookup baseline has nothing to copy and falls back to guessing the common label. Its MCC is exactly 0.000, meaning no relationship to the truth. The 3-mer model scores 0.357 on the random split and 0.461 on the cluster-aware one. Thus the trained models do carry real signal that transfers to unfamiliar proteins. It is simply worth less than homology wherever homology is available, and this is the clearest view we have of the quantity the project set out to isolate.

9 · Conclusions

We set out to measure how much of a protein classifier's score comes from copying labels off similar training proteins. We can now answer that, with some qualifications.

Homology does inflate results, and we can put a number on it

On enzyme classification, removing close relatives from the test set costs the 3-mer model 0.055 of ROC-AUC on average across five divisions of the data, and costs the lookup baseline 0.154 of MCC. Performance rises steadily with similarity, from 0.769 for proteins below 30% identity to 0.944 for those above 90%. Proteins with no relative at all are the hardest of any group.

On DeepSol the same measurement returns nothing, for a reason

The identical pipeline finds no gap on the solubility dataset. This is not because homology fails to help there. It is because two effects of similar size cancel. The cluster-aware split keeps a large amount of partial homology, while the random split keeps three times as many protein pairs whose labels disagree. Those unreliable pairs sit above 90% identity, which is where the dataset's own duplicate removal was applied.

Thus a single average score on this dataset cannot be interpreted without also reporting results by similarity. Anyone comparing methods using the aggregate number alone will understate how much homology is contributing.

Simple models are much worse than lookup, but not useless

On the enzyme task, copying the nearest relative's label beats both trained models by a wide margin, on both splits and in every similarity band. Where no relative exists, the situation reverses completely. The lookup baseline drops to an MCC of exactly zero while the 3-mer model holds at 0.357 to 0.461. Thus these models do learn something that transfers to unfamiliar proteins, and it is worth measuring, but on this task it is worth less than homology wherever homology is available.

The feature representation decides whether any of this is visible

Amino acid composition shows no reliable gap on either dataset. Across five divisions its average gap is 0.004 with a spread of 0.008, and two of the five are negative. A study using only composition features would have reported a null result even on the clean dataset. Everything we can claim rests on the 3-mer model.

10 · Limitations

Each item below weakens one of the claims above. We list them because a result is only as useful as the reader's ability to judge how far it goes.

The cluster-aware split is not free of homology

8.9% of its test proteins on solubility, and 11.8% on enzyme, still have a closest match that meets our own clustering criteria. On enzyme the figure rises to 18.0% if any qualifying match counts rather than only the closest. This happens because MMseqs2 clustering is greedy, meaning it assigns each sequence to a representative without comparing every possible pair. The cluster-aware scores are therefore slightly optimistic, and the analysis by similarity band is the more reliable view.

Only one similarity threshold was tried

Everything uses 30% identity with 80% coverage. A 50% threshold is the obvious check and we did not run it, because it requires redoing the clustering, the splits and every model fit. We expect a looser threshold to group more proteins and therefore produce a stricter split, but we have not measured it.

Weak models were a deliberate choice, and it cost us

Logistic regression on counts of short subsequences is far below the state of the art, which uses protein language models. We chose it so that the comparison between splits would be attributable to the split alone. The cost is visible in the composition results, which show no reliable effect on either dataset. A stronger model might show a larger gap, or might generalise better and show a smaller one. We cannot tell from this work.

The explanation for the label collapse is inferred, not proven

The change in label agreement happens at 90% identity, which is where DeepSol applied its duplicate removal. That is strong circumstantial evidence but the preprocessing code is not published, so we cannot confirm the mechanism.

Regularisation was tuned once, not per fold

In the five-fold variance check, the regularisation strength chosen on the first fold was reused for the others. This slightly favours the first fold, which is the one that produced the largest gap. Tuning within each fold would be more correct and would most likely reduce the reported spread rather than increase it.

Bands differ in size and in label balance

The cluster-aware split's 70 to 90% band holds 386 proteins on solubility and 718 on enzyme, so estimates there carry much more uncertainty than the large bands. Label balance also varies between bands, which means accuracy should only be compared within a band and never across them. The no-relative group shows why. Only 14.6% of its proteins are enzymes, so the lookup baseline reaches 85.4% accuracy there purely by calling everything a non-enzyme, while its MCC is zero.

Best-case thresholds were found using the test set

The threshold sweep in section 4 picks the best threshold by looking at the test set, which is not a legitimate procedure. Those figures are an upper limit on what tuning could achieve, not a result. The conclusion we draw from them is only that the available gain is small.

The enzyme negatives are defined by absence of evidence

A protein with no EC number is usually one that nobody has tested, not one shown not to be an enzyme. Requiring a described function and confirmed existence reduces this problem but does not remove it.

A limit that applies to this whole area of work

Solubility labels of this kind record whether an experiment finished, not whether a protein is soluble. Records frequently show that work stopped without giving a reason, so an insoluble label can mean genuine clumping or can mean the project was abandoned. This places a ceiling on accuracy that no modelling choice can get past, and it is the reason we treat the 18.6% disagreement figure as a real constraint rather than a footnote.

11 · Reproducing this

All code, the pipeline script and the saved results are in the project repository: github.com/adnair06/homology-leakage-study

The enzyme experiment runs from one script that takes the dataset as configuration. The solubility experiment is a numbered series of notebooks. Both perform the same stages. 

# environment
python3 -m venv .venv && source .venv/bin/activate

# or one stage at a time

Stages

  1. Load the data, attach labels, report label balance, duplicates, alphabet and length distribution.
  2. Apply the length and character filters, checking that no sequence is emptied.
  3. Write the sequences in FASTA format, which is the plain text format these tools expect, then cluster with MMseqs2.
  4. Report the cluster structure: how many clusters, how many contain a single sequence, and the largest.
  5. Build the cluster-aware split first, then match the random split to it.
  6. Build the composition and 3-mer features.
  7. Search every test protein against the training set, then derive the lookup baseline and the similarity bands.
  8. Fit the logistic regressions, choosing regularisation strength by cluster-aware cross-validation inside the training set.
  9. Score by band and draw the figures.

Where the per-band figures come from The enzyme run originally reported only ROC-AUC per band. The accuracy, MCC and lookup baseline figures shown here were recomputed from the saved outputs, namely splits.parquet, best_hits.parquet and preds_logistic.npz. That recomputation reproduces all four reported aggregate ROC-AUC values and all fourteen reported band sizes exactly, which is what allows us to trust the figures derived alongside them.
A problem worth recording When the 3-mer features are normalised to sum to one, each individual value is around 0.003. At the default regularisation strength the model stopped after six iterations with every predicted probability below 0.5. It therefore predicted the common label for all but 2 of 13,885 test proteins, giving an F1 of 0.0007, while still reporting a ROC-AUC of 0.65. The ordering of proteins was fine and only the threshold was wrong. Weakening the regularisation fixed the predictions and barely changed the ROC-AUC. This is a useful reminder that ROC-AUC and F1 fail in different ways, and that one can look healthy while the other does not.
